# 入力時の同種牌上限

2026-10-04。手牌に同じ種類を5枚以上入力できる問題への修正。

## 動作

- 手牌（既存のツモ牌を含む）、副露の実牌、ドラ表示牌を合わせ、各34牌種は4枚まで。赤五と通常五は合算し、各色の赤五1枚という既存ルールも維持する。
- 入力先ごとに、追加すると上限を超えるパレットの牌を無効化する。鳴きは押した1枚だけでなく、組み立てる3枚または4枚をまとめて確認する。槓は実牌4枚で数える。
- 薄くなった牌の理由を「追加できない牌と理由」で確認できる。削除・戻す・入力先の切替後に使用可否を再計算する。
- OCR結果を手動修正するときは、置き換える元の牌を除いて判定する。学習後の一括再読取で同種5枚以上や赤重複になる場合は、一括再読取を採用せず指定した修正を保つ。OCR精度そのものを改善する変更ではない。
- 不正な既存問題や読み取り結果は自動で削らない。編集時の手牌切り詰めをなくし、修正できるよう元の牌を表示する。6枚目以降の不正なドラ表示牌にも削除操作を用意する。OCR結果に上限違反があれば作成画面への自動移動を止め、修正または除外を案内する。
- 部分形の学習メモは引き続き保存できる。保存時の既存validationは維持し、UIを経由しない不正な保存も従来通り拒否する。保存schema・正解判定・画像認識モデル・保存破損復旧は変更しない。

## 検証

修正前は同種5枚の入力が成立し、保存時だけ拒否されることをDOM操作で再現した。修正後は連続入力、赤通常、入力先をまたぐ枚数、チー・ポン・3種の槓、削除・戻す、既存ツモ、OCRの置換・再読取、不正データ保持を回帰する。OCR検査には認識結果fixtureを用い、実画像の認識精度の証明にはしない。

新しい14試験は成功。独立レビューでも14件を再実行し、OCR同牌再選択、複数牌種の段階修正、赤から通常への修正、6枚のドラ表示牌の保持/除外、赤入りポン/槓を含む追加5試験が成功した。受け入れ・残数調整との結合では159件中158成功、既存A44検索性能だけが526.5msで200ms閾値を超えて失敗。型チェック・ビルドは成功した。

実ブラウザの起動制限が継続しているため、実描画・狭幅・実機操作は未確認。DOM試験を実画面検証とは扱わない。公開・mainへの統合は別手順。
