# 打牌別の受け入れ

2026-10-04。当初仕様の対象外だったシャンテン・打牌別受け入れを追加する。公開サイトへの反映は別途行う。

追加依頼による解析画面内の残枚数手動調整は [残枚数調整設計](残枚数調整設計.md) を参照。ここに記す理論残枚数が初期値と上限になり、構造シャンテンは調整で変えない。

- 作成、詳細、テスト回答後で同じ解析部品を使う。回答前には表示しない。
- 14枚相当は各打牌後、13枚相当は現在の受け入れ。同一コードの重複打牌をまとめ、赤五と通常五の打牌は区別する。順序は牌順で、最善打牌の推薦ではない。
- 牌は赤五を通常五にまとめた四麻34種。現データに三麻ルール選択はないので点数や空席から推定しない。
- 通常形・七対子・国士無双の最小シャンテン。固定した副露があれば（暗槓も含む）通常形のみ。槓は1面子として枚数相当を数える。
- 有効牌はツモ後に最小シャンテンが厳密に下がる牌。テンパイ0、完成形−1。役・フリテン・和了の合法性は判定しない。
- 通常形は各牌種4枚以内の完成形に至る最小追加枚数−1。色ごとの順子開始数、刻子、雀頭を動的計画で全探索し、4−固定面子数と雀頭1組に合成する。5枚目を必要とする架空の完成形は除外する。既知の他所にある牌による枯れはシャンテンを変えず、残枚数で区別する。
- 理論残枚数は4−（現在の手牌＋ツモ＋副露の実牌＋ドラ表示牌）。打牌は見えている場所へ移るだけなので引いたまま。赤通常合計4枚。河全体や他家の手牌は未入力なので実際の山残数ではなく、入力済み情報上の上限。0枚の形上の有効牌も別に示す。
- 部分形、5枚以上の同種、重複赤、壊れた副露や不正な牌は理由を示して計算しない。保存側の既存の許容は変えない。
- 新依存、外部送信、データschema変更なし。純TypeScriptによる独自実装。既存画像部品を再利用。

## 受入と戻す条件

独立な完成形列挙oracle、通常/特殊形、13/14枚相当、槓、四枚使い、赤、枯れ、同時不足、入力不変を検証する。全既存テスト/typecheck/build、320幅で入力→保存→詳細→回答後、共有/復習回帰を行う。A44の既知性能閾値失敗は隠さない。異なる計算値・入力待ち・保存/回答の変化が出れば解析部品を外して戻せる。

## 参照（コードの転載・依存採用なし）

- 開発引継ぎ: `docs/引継ぎ仕様.md` 全文、仕様 `docs/仕様書.md`
- 作者によるシャンテン定義・3種の形の説明: https://github.com/tomohxx/shanten-number （LGPL-3.0、採用せず）
- 不足枚数と既知牌を区別する研究: https://arxiv.org/abs/2108.06832 （一般麻雀の研究で、リーチの特殊形を直接実装する根拠にはしない）
- 有効牌の定義（ツモでシャンテンが下がるか完成する牌）: 佐藤・西村・保木 2014 §5 / 付録A.1 https://www.tanaka.ecc.u-tokyo.ac.jp/wp/wp-content/uploads/2014/04/IPSJ-GI14031011.pdf 。面前研究なので副露の規則を証明する出典ではない。
- 5枚目を要求する形を除外する考え方: https://arxiv.org/html/2108.06832v1 Definition 3 / Example 1。論文の完成0の不足枚数に対し、ここでのシャンテンは完成−1である。
- 天鳳公式牌理の4例を独立担当が実UIで照合: https://tenhou.net/2/ 。全打牌候補・暗槓まで公式照合済みとは扱わない。代表例は独立fixtureとしてテストに収録。
- 天鳳の流局時の形式聴牌規定と、この機能の手牌構成上のシャンテンは別。固定ポン111m＋純手牌1m234p567p789sは本機能で1シャンテン。ドラ表示や河で待ちが枯れた通常のテンパイは0のまま、受け入れ0種0枚と表示する。
