# 記録画像の共有

記録帳の「Xに記録を投稿」から、日付・今日と累計のテスト／確認／教材学習回数を確認できます。画像と投稿文は、画面を開いた時点の同じ集計から作成します。累計はグラフの表示期間より前も含め、その端末の今日までの記録を使います。問題名、教材名、コメント、私用メモ、画像添付、正答率や称号を送信内容に含めません。記録は変更しません。

画像には、ダイアログを開いた時点の適用テーマ（ノーマル・クール・キュート・DOPA・MOE）を使います。集計とテーマは開いている間は固定し、開き直すと取り直します。

対応する端末では「画像付きで共有」を主な操作として表示します。作成済みの PNG ファイルと文面を Web Share API に渡し、利用者が共有先で X を選びます。画像をいったん保存して選び直す操作は不要です。ファイル単独の機能検出で画像対応を確認し、画像と文面の組み合わせが非対応の場合も「画像を共有」で PNG を渡せます。この場合は文面をコピーして共有先へ貼り付ける案内を表示します。

「投稿文をコピー」は別のボタン操作です。共有ボタンから自動でクリップボードを書き換えたり、コピーを待って共有のための利用者操作を失ったりしません。コピー API が使えない場合は表示中の文面を選択し、端末のコピー操作を案内します。

共有先に X が出るか、画像と文面の両方を受け取れるかは端末・共有先アプリによります。サイトから候補アプリや選択された共有先を特定することはできません。共有先が一部の情報を受け取らない場合もあり、API の正常終了を X での添付成功や投稿完了とは扱いません。共有先の画面で画像と文面を確認し、投稿自体は利用者が確定します。

共有に非対応の場合は、「画像を保存」→「Xの投稿画面を開く」の手順を最初から表示します。対応端末では「画像が添付されない・Xが見つからないとき」に折りたたみ、共有 API のエラー時は展開します。X の投稿画面には文面を渡し、利用者が保存画像を添付します。この保存手順では画像は自動添付されません。キャンセルやエラーの後に自動で画像を保存したり、別画面を開いたりしません。キャンセルと共有先なしは同じ `AbortError` のため、どちらとも断定しません。

X の Web Intent へローカル PNG を直接渡す公式の方法は確認できていません。別の仕組みである X API のメディア送信と投稿には、開発者アプリ、利用者の OAuth 認証・書き込み権限、API の料金条件などの検討が必要です。今回の実装では認証、API 登録、課金、外部への画像アップロード、代理投稿を追加していません。

## 参照した一次資料

- [Web Share API — W3C](https://www.w3.org/TR/web-share/): ファイル共有、機能検出、利用者操作に基づく呼び出し、共有先を端末が提供する仕組み。
- [The User Activation API — WebKit](https://webkit.org/blog/13862/the-user-activation-api/): 共有操作に必要な一時的な利用者操作の扱い。画像は共有ボタンを押す前に生成します。
- [X のポストボタン — X ヘルプ](https://help.x.com/en/using-x/add-x-share-button): 文面・リンクを用意した投稿画面から、利用者が編集・投稿する仕組み。ローカル画像を Web Intent で自動添付する方法は確認できていません。
- [Async Clipboard API — WebKit](https://webkit.org/blog/10855/async-clipboard-api/): コピーも明示的な利用者操作の中で行います。
- [Upload media — X](https://docs.x.com/x-api/media/upload-media): OAuth の `media.write` 権限を使う API メディア送信。
- [Create Posts — X](https://docs.x.com/x-api/posts/create-post): API での投稿には `tweet.write` などの OAuth 権限が必要です。
- [Manage Posts — X](https://docs.x.com/x-api/posts/manage-tweets/introduction): 開発者アカウント、Project/App、利用者アクセストークンが前提です。
- [X API pricing — X](https://docs.x.com/x-api/getting-started/pricing): API は従量課金方式。最新の条件は公式資料で確認します（2026-10-05 確認）。

## 検証範囲

集計・タイムゾーン・テーマの固定・画像描画と、共有 API の成功／キャンセル／エラーを分けて試験します。画像と文面の共有、画像単独の共有、機能検出の例外、コピー成功／非対応／拒否、画像の準備前と共有中の操作、閉じた後の遅延結果、再試行、折りたたみを含むフォーカス移動を確認します。CI は合成データだけを使い、実際の PNG を生成・保存して描画を確認します。共有 API はテスト用実装に置換し、X へのリンク先は通信前に遮断して検査します。実際の OS 共有画面、X アプリでの画像・文面受領、投稿完了は CI の合格範囲に含みません。
