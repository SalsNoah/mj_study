# 麻雀学習帳 仕様書 v1.0

作成日：2026-09-25／対象：Cursorによる新規実装

## 1. 目的と合意事項

麻雀で学んだ牌姿・考え方を短時間で記録し、牌の形とタグから探し、繰り返し復習するスマホ優先のWeb学習帳。正解を定めないメモと、正解を設定した何切るクイズを同じデータで扱う。

| 項目 | 確定した要望 |
|---|---|
| 利用者 | 複数人がそれぞれ自分の学習帳を利用 |
| 保存・認証 | ローカルストレージ保存。ログインなし・サーバー保存なし |
| 画面 | スマホ優先、PC対応 |
| 牌姿入力 | 牌ボタン、手牌、ツモ牌、赤五萬・赤五筒・赤五索、副露、自動理牌 |
| 問題情報 | 正解任意、解説、自分のメモ、ドラ表示牌、場風、自風、巡目、点数・順位・本場、参考画像、出典URL |
| 整理・復習 | タグ、手動確認回数、クイズ、自動正誤判定、理解度、ランダム・苦手優先・タグ別出題 |
| 画像 | 参考画像を添付して保存／作成した牌姿をPNG保存 |
| 検索 | 一部の牌を含む検索、234m567p形式、色替え、5中心反転、数字のずれ |
| 共有 | 選んだ問題をデータ入りURLで共有。画像は含めない |

同一サイトでもブラウザ・端末が違えば別の学習帳になる。同じブラウザの同じプロファイルを使う人同士は同じデータを見る。アカウント、端末同期、同一ブラウザ内の利用者切替は初期版の対象外。

## 2. 実装用に採用する補完仕様

以下は追加ヒアリングを要しないよう採用した設計上の初期値であり、ユーザーが個別指定した要件ではない。

- 仮称「麻雀学習帳」。日本式四人麻雀を基本にする。三人麻雀専用の抜きドラは対象外。
- 正解は複数指定可能。正解なしの問題も復習対象にでき、自己評価で学ぶ。
- 解説は共有対象にできるが、自分のメモ・学習履歴は共有しない。
- 部分的な牌姿も保存可能。枚数が通常の対局状態と違うときは警告するが、学習メモの保存は妨げない。
- 安全なデータ移行のため、全件JSONバックアップと復元を必須にする。
- 利用者の問題情報は外部に送らない。解析・広告・外部画像読み込みは初期版に入れない。
- 添付画像もlocalStorageへ保存する。IndexedDBやクラウドに無断で置き換えない。

## 3. 初期版に含めない機能

AIによる正解生成、牌効率・シャンテン計算、画像からの牌認識、他人の公開問題一覧、ランキング、コメント、通知、定期復習スケジューラ、河や卓全体の再現、自由ドラッグ理牌、ネイティブアプリ、オフライン起動保証。出典URLの自動取得もしない。

## 4. 主要画面と操作

### 4.1 学習帳一覧

下部ナビゲーションは「学習帳／作成／復習／設定」。一覧は検索、タグ絞り込み、並べ替え、問題カードで構成する。

カードにはタイトル、手牌の縮小表示、タグ、確認回数、理解状態、最終確認日時を表示。「正解あり／正解なし」を識別できる。タイトル未入力時は「無題の問題」。並べ替えは更新順（初期値）、確認回数の少ない順、最終確認が古い順。未確認は古い順の先頭。文字検索はタイトル・解説・自分のメモ・タグを対象とし、牌姿検索とは入力欄を分ける。各条件はANDで絞り込む。複数タグはORを初期値とし「すべて含む」に切替可能。

空状態では新規作成へ誘導。サンプルは任意の「サンプルを追加」から導入し、起動のたびに勝手に追加しない。

### 4.2 作成・編集

1. タイトル（任意）。手牌／ツモ／副露／ドラ表示牌の入力先を明示する。
2. 萬子・筒子・索子・字牌の牌パレットからタップして追加。牌には画像と読み上げ名を付ける。
3. 入力済みの牌を選択して削除。最後の追加を戻すボタンを置く。全消去には確認を入れる。
4. 「理牌」で手牌だけを萬→筒→索→東南西北白發中に並べる。同ランクの五は通常→赤。ツモ牌は右端に間を空けて保持する。理牌は初期ONで、OFF時は追加順を保持。
5. 副露は種類を選んで専用入力。完成前は確定できない。副露全体の編集・削除が可能。
6. 正解設定をONにしたときだけ、手牌・ツモ牌から正解牌種を複数選ぶ。副露牌は選べない。
7. 解説、自分のメモ、タグ、対局条件、参考画像、出典を入力して保存。

基本情報を先に見せ、対局条件・参考資料は折りたたむ。保存は明示ボタン。離脱時は未保存変更を警告する。保存失敗時に成功表示を出さず、入力を画面に保持する。

### 4.3 詳細

牌姿、条件、タグ、解説、自分のメモ、画像、出典、学習履歴を表示。編集、複製、削除、PNG保存、URL共有を用意する。複製は新IDと学習履歴ゼロで作成する。

「確認した」を押すと確認回数+1、最終確認日時更新。「取り消す」を短時間表示し、その操作による加算だけを戻す。同じ表示中に連打しても1回とし、取り消すか、詳細の再訪・次の復習セッションで再び加算可能にする。問題を開く、クイズに答える、解説を読むだけでは加算しない。

### 4.4 復習

開始時にタグ、出題順（ランダム／苦手優先）、問題数（10／20／全件）を選ぶ。候補が少なければ存在する件数で開始し、0件なら開始不可と理由を表示。同一セッション内で同じ問題は重複しない。

正解あり：牌姿表示→手牌またはツモ牌を選択→「回答する」→正誤と解説表示→理解できた／まだ不安を任意で記録→任意で「確認した」→次へ。

正解なし：牌姿を見て考える→「解説を見る」→自己評価→任意で「確認した」→次へ。自動判定せず、正答率の分母にも含めない。

正解の同一牌が手牌内に複数ある場合はどの位置を選んでも正解。通常五と赤五は正解判定では別牌種として扱い、両方正解なら両方登録する。ツモ切り／手出しの位置差自体は判定しない。

回答確定は1問につき1回だけ。確定後の再押下で回答履歴を増やさない。問題文に解説・正解・自分のメモ・タグ・出典・参考画像を先に出さない（ネタバレ防止）。解答後に表示する。

苦手優先は、(1)自己評価が「まだ不安」または直近自動判定が不正解、(2)未学習、(3)その他、の順。区分内では最終復習日時の古い順、同値はランダム。高度な学習アルゴリズムは不要。

結果画面は出題数、自動判定の正解数／回答数、正答率、自己評価の件数を表示。正解なししかない場合は正答率を「—」。途中終了時も確定済み記録を残すが、スキップ・未回答は正答率に含めない。

### 4.5 設定

保存量の目安、JSONバックアップ、JSON復元、サンプル追加、全件削除。全件削除は確認を必須にし、直前バックアップを案内する。ブラウザのデータ削除で消えること、別端末には自動同期されないことを短く表示する。

## 5. 牌と対局条件の仕様

### 5.1 牌コード

- 数牌：1m〜9m、1p〜9p、1s〜9s。m=萬、p=筒、s=索。
- 赤五：0m、0p、0s。五としてのランクは5、赤属性を別に持つ。
- 字牌：1z=東、2z=南、3z=西、4z=北、5z=白、6z=發、7z=中。
- 花牌・8z・9z・0zは扱わない。
- 牌表示をUnicode麻雀文字だけに依存しない。同梱SVG等で端末差を抑える。画像の権利はREADMEに記載。自作図形でも可。

### 5.2 副露

チーは同色で連続する数牌3枚、ポンは同牌種3枚、明槓・暗槓・加槓は同牌種4枚。赤五は組の成立判定で通常五として数える。チーは左家からのみ。ポン・明槓は左家／対面／右家、加槓は元のポンの取得元を指定。鳴いた牌のindexを保持して横向き表示。加槓は横牌上に1枚重ねる。暗槓は両端を裏面表示し、データには4枚とも保持。正しい成立条件は保存時にも検証する。

### 5.3 枚数と整合性

手牌は最大14、ツモは0〜1、副露は最大4組、ドラ表示牌は最大5枚。通常の14枚形は「手牌+ツモ+副露組数×3=14」（槓を3枚相当で計算）。13枚形や部分形も保存可能。通常形から外れる場合は非阻害の警告。

手牌・ツモ・副露・ドラ表示牌を合計し、赤通常を合わせ同一牌が5枚以上なら保存不可。初期版では各色の赤五は最大1枚。検索入力にも同一牌4枚上限を適用する。正解指定ONで正解0枚、または編集で消えた牌種が正解のままなら保存不可。正解OFFなら正解配列を空にする。手牌・ツモ・副露がすべて空の問題は保存不可。

### 5.4 任意の条件

場風（東南西北）、局番号（1〜4）、自風、巡目（1〜30）、本場（0〜99）、供託（0〜99）、東南西北それぞれの持ち点（-100000〜200000の整数）、自分の順位（1〜4）。空欄を保持し、未入力を0点と混同しない。点数合計や順位は自動で断定しない。ドラは「ドラ表示牌」と明記し、ドラそのものと混同させない。

## 6. タグと文章

タグは問題に複数付与可能。既存候補から選択／新規入力。前後空白除去・NFKC正規化後の同名重複を防ぐ。英字大小は同一とみなす。1タグ20文字、1問10タグ、全体200タグ。タグ名変更は全問題に反映。タグ削除は問題自体を消さない。

タイトル100文字、解説4000文字、自分のメモ4000文字、出典URLはHTTP/HTTPSのみで最大2048文字。文章はプレーンテキスト表示。HTMLは実行しない。URLは別タブで開き、入力内容を勝手に取得しない。

## 7. 牌姿検索（特に厳密に実装）

### 7.1 入力と共通条件

牌パレットと文字入力を相互同期させる。文字例：234m567p11z、11123m、05p。数字群に必ずm/p/s/zを付ける。空白・全角英数字は正規化し、大文字の色記号も許容。途中入力はエラー表示だけにして検索せず、無効文字を黙って捨てない。

初期値は「指定した牌を含む」。牌の順序でなく枚数付き多重集合で比較。11mなら一萬が2枚以上必要。検索範囲は手牌+ツモを初期値とし、「副露を含む」を選択可能。ドラ表示牌は対象外。「完全一致」は選択範囲の牌集合がちょうど一致する追加モード。

### 7.2 色替え・反転・数字のずれ

「色替え」「反転」「数字のずれ」を個別にON/OFFでき、初期値はすべてON。すべてOFFで指定牌そのままの検索。以下を同時に満たす変換だけを認める。

1. 色替えはm/p/s全体の1対1置換（6通り）。別の2色を同じ1色に統合しない。
2. 各数牌色について、その色の検索牌すべてを一括で r→10-r に反転するか、しないかを選ぶ。3色の独立した反転は最大8通り。これは未指定だった複数色の扱いに対する補完仕様。
3. 反転後、各色の検索牌すべてに同じ整数dを加える。結果がすべて1〜9に収まるdだけを列挙する（d=0も含む）。色ごとに別のdを使えるが、同じ色の中で牌別・ブロック別のdは使えない。色替え・反転・移動の候補を重複除去し、いずれかが対象多重集合に含まれれば一致。
4. 字牌は置換も反転もしない。東を南や白に置き換えない。
5. 数字のずれは間隔と重複枚数を保つ平行移動だけ。234→345、11123→22234は一致。234→356は一致しない。9から1への折り返しは禁止。
6. 検索時は赤五と通常五を初期値で同一視するため、赤五を通常のランク5に変換してから数字移動できる。「赤牌を区別」をONにした場合は赤属性を保持し、移動後の赤牌が5以外になる候補は棄却する。色替え・反転でも赤属性を保持する。

反転・数字移動は検索牌全体に対する上記ルールで行い、牌ごとに別々の変換を選ばない。候補数が増えるため、全候補の直積を無制限に構築せず、色対応を決めた後に色別の枚数照合・早期棄却を行う。検索入力は150ms程度のデバウンスを入れる。表示順・ツモ位置・副露の区切りはこの検索の一致判定に含めない。副露を含む場合も、各副露の合法性を再判定して検索結果を落とさない。

| 検索 | 対象 | 色替え・反転・数字移動ON時の期待 |
|---|---|---|
| 234m | 234p | 一致 |
| 234m | 678p | 一致 |
| 11123m | 78999s | 一致 |
| 234m | 345p | 一致：数字のずれ |
| 11123m | 22234p | 一致：数字のずれ |
| 234m | 356p | 不一致：間隔が異なる |
| 11123m | 77789s | 一致：数字のずれ |
| 11123m | 77799s | 不一致：重複構造が異なる |
| 11m | 1p | 不一致：枚数不足 |
| 12m12p | 1122s | 不一致：色の統合は禁止 |
| 12m34p | 89s34m | 一致：色別の一括反転 |
| 1z | 2z | 不一致 |
| 5m | 0p | 赤を同一視なら一致、区別なら不一致 |

検索結果カードに「そのまま／色替え／反転／数字のずれ」の一致理由を表示。複合変換は該当ラベルを併記し、複数候補がある場合は変換要素の最も少ない説明を優先する。同一問題を重複表示しない。

## 8. 参考画像と牌姿PNG

### 8.1 添付

JPEG/PNG/WebPを1問最大3枚、元ファイル1枚10MB以下。読込失敗・不正形式は理由を表示。ブラウザ内で再描画し、長辺1280px以下を初期値として圧縮。変換後の1枚は150KiB以下を目標に品質・解像度を調整し、文字が読めない場合はユーザーが中止できるプレビューを出す。上限を満たせない場合は添付不可とし、勝手に原寸のまま保存しない。

写真の向きを正しく扱い、再描画した画像だけをData URLとして保存。画像内容はURL共有から除外。削除は編集保存時に反映し、キャンセルなら維持する。

### 8.2 PNG出力

手牌・ツモ・副露を出力。ドラ表示牌があれば区別した別段に含める。解説・メモ・参考画像・学習履歴は含めない。白背景、十分な余白、通常牌と赤牌の区別、横牌・加槓の重なりを保つ。長辺1600px以上を基本とし、表示用と同じ牌データ・描画定義を共有して取り違えを防ぐ。

PNGはブラウザ内生成。スマホで直接ダウンロードできない場合は画像プレビューから保存できる導線を用意。ファイル名はmahjong_YYYYMMDD_HHmmss.png。外部画像・外部フォントに依存しない。

## 9. 保存とバックアップ

### 9.1 保存方式

localStorageの単一ドキュメントキー mahjong-study:v1 に、スキーマ版・更新リビジョン・全問題・タグ・学習情報・画像・設定をJSON保存。変更の都度ではなく、保存・解答確定・確認などの確定操作時に保存。setItem成功後だけ確定UIに更新する。保存処理をRepositoryにまとめ、UIから直接アクセスしない。

保存予定文字列のUTF-16概算サイズを算出。3MiBで注意表示、4MiBをアプリの保存上限とする。ブラウザごとの実容量を保証する数字ではなく、これ未満でもQuotaExceededError等を捕捉する。画像数を勝手に増やさない。バックアップ・画像削除を案内し、既存データを自動削除しない。履歴増加で保存できない場合も成功を装わない。

同一ページのリビジョンと保存済みリビジョンが異なる場合は競合として保存停止。storageイベントで別タブ変更を検知し、再読込を案内。複数タブを同時編集して無言で上書きしない。localStorageは強いトランザクションを保証できないため、完全な同時書込排他は初期版で保証しない。

読込時はスキーマ検証。破損・未知の上位スキーマを検知したら自動初期化せず、元データ書き出しと復旧案内を出す。アクセス自体が拒否された場合も明示する。

### 9.2 バックアップ

全問題・タグ・画像・学習記録・設定・schemaVersionをJSON出力。インポートは最大20MiB、JSONと全項目の検証後、件数・画像数を確認画面に表示。「追加」と「全置換」を選べる。追加は問題ID・履歴IDを再採番しタグを名前で統合、取り込んだ学習記録を対応する新IDに結び直す。全置換前は現データのバックアップを案内。容量検証後、単一setItemで反映し、失敗なら元データを維持する。

## 10. URL共有

### 10.1 方式

固定されたHTTPSのアプリURLのフラグメントを使う：<app-origin>/<base-path>/#share=v1.<payload>。payloadは許可フィールドだけから構築したJSONを圧縮してURL安全な文字列にしたもの。query文字列に問題本文を置かない。復号にサーバー通信を要しない。同じ圧縮方式・版のエンコーダーとデコーダーをテストする。

本体を静的ホスティングすることと、問題データをサーバー保存することは別。共有先が使うためにはアプリ自体のホスト先が必要。実装段階ではローカル検証まで行い、実際の公開作業は別途ユーザー指示に従う。localhostのURLは他者向け共有に使えない旨を表示する。

### 10.2 含める情報

必須：共有形式版、タイトル、手牌、ツモ、副露、ドラ表示牌、対局条件。

共有画面で選択：正解・解説（初期ON）、タグ（初期OFF）、出典URL（初期OFF）。正解・解説をOFFにしたときは両方ともペイロードから完全に除く。

常に除外：参考画像、自分のメモ、確認回数、回答履歴、理解度、内部ID、アプリ設定。元のProblemを丸ごとserializeしない。共有内容のプレビューを確認してからコピーする。

### 10.3 共有先

受け取った問題は読取専用のプレビューとして開き、元の学習帳に自動保存しない。「自分の学習帳に追加」で新ID・学習履歴ゼロのコピーを保存。同一URLの再取込時は重複の可能性を案内し、勝手に上書きしない。追加するまで受信者の学習記録は書き換えない。正解が含まれる場合は「解説を見る」で表示できる。

### 10.4 制限と保護

URLを知っている人は読める。暗号化・アクセス制限・取り消し機能ではない。共有後の元問題の修正は反映されない。正解を含めたURLの中身は解析できるため、厳密な試験用途には使わない。

生成URLは8000文字まで（アプリの運用上限であり、全SNSの対応保証ではない）。超えたら文字を勝手に省略せず、解説等を外す／短くするよう案内。デコーダーもURL長上限・展開後JSONの64KiB上限・スキーマ・文字数・牌成立条件を検証。上限を設けてから展開できる実装を選ぶ。壊れた入力、未知の版、異常なオブジェクトを安全に拒否し、既存データを変更しない。

## 11. データ設計

型は次を基本とし、実装時に厳密なTypeScript型と実行時バリデーションへ落とす。

```ts
type TileCode = string; // 上記の37種類のみ許容する厳密型へ展開
type Meld = {
  id: string;
  type: 'chi' | 'pon' | 'openKan' | 'closedKan' | 'addedKan';
  tiles: TileCode[];
  from: 'left' | 'opposite' | 'right' | null;
  calledIndex: number | null;
  addedIndex: number | null;
};
type Problem = {
  id: string; title: string;
  concealed: TileCode[]; drawn: TileCode | null; melds: Meld[];
  doraIndicators: TileCode[];
  answerEnabled: boolean; acceptedDiscards: TileCode[];
  explanation: string; privateMemo: string; tagIds: string[];
  context: { roundWind: string | null; handNumber: number | null;
    seatWind: string | null; turn: number | null; honba: number | null;
    riichiSticks: number | null; ownRank: number | null;
    scores: { east: number | null; south: number | null;
      west: number | null; north: number | null } };
  attachments: { id: string; dataUrl: string; width: number; height: number }[];
  sourceUrl: string; createdAt: string; updatedAt: string;
};
type StudyState = {
  problemId: string; contentRevision: number;
  confirmationCount: number; lastConfirmedAt: string | null;
  understanding: 'unrated' | 'understood' | 'uncertain';
  lastReviewedAt: string | null;
};
type Attempt = {
  id: string; problemId: string; contentRevision: number;
  sessionId: string; questionIndex: number; at: string;
  selectedTile: TileCode | null;
  result: 'correct' | 'incorrect' | 'selfReview';
};
type Store = {
  schemaVersion: 1; revision: number;
  problems: Problem[]; tags: { id: string; name: string }[];
  study: StudyState[]; attempts: Attempt[];
  settings: { autoSort: boolean };
};
```

日時はISO 8601 UTCで保存し表示時に端末ローカル時刻へ変換。IDは衝突しにくいランダムID。正答率はAttemptから算出し、別のカウンターとの不整合を作らない。確認回数と回答数を混同しない。

牌姿・正解・解説の内容変更時はcontentRevisionを増やし、理解度・直近復習日時を未評価に戻す。確認回数は累積のまま保持。過去回答は履歴として保持し、現在内容の正答率は現在のcontentRevisionだけで計算。タイトル・タグ・私用メモのみの編集では版を増やさない。問題削除時は関連学習状態・回答履歴も同時削除する。

## 12. UI品質

明るい生成り背景、深緑のアクセント、白い牌を基本とする落ち着いた学習道具のデザイン。強いネオンや過剰な装飾は不要。色だけで正誤・赤牌・選択状態を伝えない。

幅360px／390px／768px／1280pxで確認。主要ボタンは44px以上のタップ領域。手牌14枚は縮小して無理に選ばせず、必要に応じて牌領域だけ横スクロール。ページ全体の横はみ出しは禁止。牌選択は横スクロール中の誤タップを防ぐ。底部固定要素はセーフエリアとキーボードを考慮。入力ラベル・フォーカス・キーボード操作・画像代替テキストを用意する。

## 13. 実装構成案

React + TypeScript + Viteを提案構成とする。既存プロジェクトがあればその構成を尊重し、大規模移行しない。版は実装環境で互換性を確認して固定する。純粋関数として牌コード変換、理牌、副露検証、検索変換、正誤判定、共有データ抽出を分離する。

推奨分割：domain/tiles、domain/search、domain/quiz、domain/share、storage/repository、features/editor、features/library、features/review、features/settings、components/Tile、export/renderTiles。UIとPNGは牌素材・描画定義を共有。検索はこの規模ではローカル走査でよく、複雑な検索サーバーを作らない。
