# スマホUIの整理

2026-10-04。計算ロジック、保存・共有の形式、同種4枚の入力上限は変更しない。

## 情報の優先順位

- 作成は対局条件→牌姿→全牌一覧を同じ画面に並べる。牌種や対局条件を切り替えるタブは置かず、連続入力を優先。解説・メモ・参考資料だけを必要時に開く。未保存入力は折り畳みでも保持。保存は上部ヘッダーに置き、牌を覆わない。解説等の入力不正時は該当欄を開く。
- 作成の入力先は従来の「手牌／ドラ表示牌／明順子／明刻子／明槓子／暗槓子／加槓子」。萬子・筒子・索子・字牌を従来の4段一覧で常時表示し、異なる牌種をそのまま連続で選べる。これは小さい牌幅と一覧性のトレードオフを伴う。学習帳等のパレット配置は変えない。
- 残枚数は全消去の右。34種の個別ステッパーを廃止し、牌種の切替、牌画像と数、選択した牌の共通入力欄に整理。上限・無効入力・0・個別/全リセットを維持する。未反映の不正入力は牌選択の切替時に破棄し、最後に反映済みの値を保持する。
- 受入れは枚数の多い上位3候補を初期表示し、「すべて表示」で全候補。同数は既存の理牌順（萬→筒→索→字牌、同色は数字順、通常五→赤五）。残枚数変更後も再集計して並べ直す。現在と各打牌のシャンテンを残し、悪化するものに「後退」と表示する。枚数順は最善打牌の判定ではない。局面変更時は3候補表示に戻す。
- 学習帳は文字検索・並べ替え・一覧を優先。牌姿やタグ検索は折り畳み、適用中の条件と解除を表示する。
- 問題詳細は牌姿と「確認した／編集」を常設し、「解説・メモ／受入れ／記録」を切り替える。共有・複製・削除は補助操作に整理。
- テストは出題条件を折り畳み、回答後は理解度と次へを独立して表示。解説と受入れは回答後だけ切り替えられる。
- 記録帳は今日・累計・現在称号を先に表示し、日別/称号を切替。設定は表示・編集/データ管理を切替。バックアップと復元は見つけやすくし、削除等の確認は維持する。
- ページ間の新規移動は先頭へ戻し、ブラウザの戻るでは記録済みのスクロール位置を復元する。

## 確認方法

`npm test`、`npm run typecheck`、`npm run build`。

`scripts/validate-ukeire-ui.mjs` は新規ブラウザプロファイルと合成牌のみを使い、localhost以外への通信を遮断する。320/375/390px、150%文字、短い高さ、開閉・タブ往復・保存・共有・テスト回答を確認し、スクリーンショットと寸法を `evidence/ukeire/` に出力する。GitHubのDraft PRでは読み取り権限だけの `Mobile UI checks` が同じ試験を実行する。

実スマートフォンのOSキーボードやピンチ操作は自動ブラウザ試験の対象外。短いviewport検証を実機キーボードの確認済みとは扱わない。
