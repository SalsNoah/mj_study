# スマホUIの整理

計算ロジック、保存・共有の後方互換、同種4枚の入力上限を維持する。

## 新規作成の初期値

新しい手入力の問題だけを東1局・東家・6巡目・全員25000点で開始する。実ドラ東に対応するドラ表示牌は北を1枚とし、北を既知牌として残枚数と同種4枚上限に含める。既存編集・画像読み取り・インポート結果の空欄や指定値は上書きしない。

## 情報の優先順位

- 作成は対局条件→牌姿→全牌一覧を同じ画面に並べる。牌種や対局条件を切り替えるタブは置かず、連続入力を優先。解説・メモ・参考資料だけを必要時に開く。未保存入力は折り畳みでも保持。保存は上部ヘッダーに置き、牌を覆わない。解説等の入力不正時は該当欄を開く。
- 作成の入力先は従来の「手牌／ドラ表示牌／明順子／明刻子／明槓子／暗槓子／加槓子」。萬子・筒子・索子・字牌を従来の4段一覧で常時表示し、異なる牌種をそのまま連続で選べる。これは小さい牌幅と一覧性のトレードオフを伴う。学習帳等のパレット配置は変えない。
- 残枚数は全消去の右。34種の個別ステッパーを廃止し、牌種の切替、牌画像と数、選択した牌の共通入力欄に整理。上限・無効入力・0・個別/全リセットを維持する。未反映の不正入力は牌選択の切替時に破棄し、最後に反映済みの値を保持する。
- 受入れは打牌後シャンテンが最小の候補に絞り、枚数の多い順に最大3候補を折りたたまずに表示する。最小群が1〜2候補なら後退候補で穴埋めしない。「その他の候補を表示」で残りを追加し、全体をシャンテンの少ない順、同じシャンテン内では枚数の多い順に表示する。その他を閉じても上位候補は残る。同数は既存の理牌順（萬→筒→索→字牌、同色は数字順、通常五→赤五）。残枚数変更後も再集計して並べ直す。現在と各打牌のシャンテンを残し、悪化するものに「後退」と表示する。枚数順は最善打牌の判定ではない。局面変更時は最小群の上位候補表示に戻す。
- 学習帳は文字検索・並べ替え・一覧を優先。牌姿やタグ検索は折り畳み、適用中の条件と解除を表示する。
- 正解ありの問題は、学習帳の一覧では「正解を表示」を初期OFF、詳細では「正解・解説を表示」まで正解印・解説・メモ・出典・解説用画像を非表示にする。表示/非表示は画面内だけで、保存データを変更しない。
- 問題詳細は牌姿と「確認した／編集」を常設し、「解説・メモ／受入れ／記録」を切り替える。共有・複製・削除は補助操作に整理。
- テストは正解あり、かつ問題ごとの出題設定が有効なものだけを対象にする。切替checkboxは置かず、旧設定がfalseでも無答題を混ぜない。問題数は数値と△▽で1刻み、対象数を上限とし0件は開始不可。Editorの出題設定と問題保存は同時に反映する。既存設定がない問題はON相当。
- テストは出題条件を折り畳み、回答後は理解度と次へを独立して表示。解説と受入れは回答後だけ切り替えられる。
- 記録帳は今日・累計・現在称号を先に表示し、日別14日/週別12週/月別12か月の折れ線を切替（週は月曜始まり）。設定は表示・編集/データ管理を切替。バックアップと復元は見つけやすくし、削除等の確認は維持する。
- ページ間の新規移動は先頭へ戻し、ブラウザの戻るでは記録済みのスクロール位置を復元する。

## 確認方法

`npm test`、`npm run typecheck`、`npm run build`。

`scripts/validate-ukeire-ui.mjs` は新規ブラウザプロファイルと合成牌のみを使い、localhost以外への通信を遮断する。320/375/390px、150%文字、短い高さ、開閉・タブ往復・保存・共有・テスト回答を確認し、スクリーンショットと寸法を `evidence/ukeire/` に出力する。GitHubのDraft PRでは読み取り権限だけの `Responsive UI checks` が同じ試験を実行する。

実スマートフォンのOSキーボードやピンチ操作は自動ブラウザ試験の対象外。短いviewport検証を実機キーボードの確認済みとは扱わない。

## 点数の3桁＋00入力

通常は符号を除く最大3桁を編集し、入力欄の枠・背景の外に末尾00を固定表示する。250は25000点、0は0点、空欄は未設定。詳細入力への切替操作は設けない。既存・インポートの100点未満の端数や100000点以上は、元の全点数を編集できる欄と枠外の「点」で保持し、丸めない。編集中に倍率を変えず、100点単位の通常範囲へ訂正した場合はblur後に3桁＋00へ戻す。

桁超えや途中符号などの未反映入力は保持し保存を止める。全点数として合法な貼付は席名と点数を明示した反映ボタン、その他は直前の有効値へ戻す操作で回復できる。回復後は対象入力へフォーカスを戻す。表示モードやdraftは保存データに追加しない。

## ドラ表示牌の5枠

作成・詳細・テスト・共有プレビューで共通の5枠を使い、ドラ表示牌は保存された順序のまま左端から表にし、残りの枠は裏向きにする。追加は右へ、削除後は左へ詰める。計算用のdoraIndicators・既知牌の減算・同種4枚制限は変更しない。PNG書出しの保存順の一覧描画は別で、今回の5枠UIの変更対象ではない。

共有プレビューの5枠実画像は、既存コンポーネントをMemoryRouter内で表示する検証専用fixtureで取得する。公開アプリの実共有URLには既存のルーティング不具合があり、今回の修正対象には含めず、実共有導線を合格とは扱わない。

## 現在の入力・画像UI

スマホではタイトルと保存を同じ行に収め、スクショ入力を全牌一覧の後ろに置く。対局条件は手牌より上のまま、点数ラベルと欄を同じ行にし重複した操作案内の縦幅を省く。文字拡大や特殊点数では自然に折り返す。`validate-study-ui.mjs` で375/390pxの640/667/740/844px高と320px・文字150%を計測し、全牌一覧の下端と下ナビの重なりを確認する。

添付画像はoptional roleで問題用/解説用を区別する。欠落・未知roleは解説用。問題用は回答前から表示し、解説用は開示後のみDOMへ入れる。タップ拡大は閉じる/Escape/背景、Tab循環と元へのfocus復帰に対応する。画像圧縮中の保存を止め、用途変更は内容改訂に含める。JSON/複製は用途を保持し、共有URL・牌姿PNGへ画像を追加しない。
